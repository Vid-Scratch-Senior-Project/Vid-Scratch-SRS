\section{Stakeholder Analysis}
\label{section:stakeholder-analysis}

\begin{enumerate}[leftmargin=80pt]
    \item \textbf{General Users and Digital Content Creators:} These stakeholders use Vid-Scratch to generate visually similar alternative versions of short videos while reducing the reliability of AI-based action recognition. They are concerned with having more control over how their videos may be interpreted, categorized, or analyzed by temporal video models.

    \item \textbf{Students, Researchers, and Educators:} These stakeholders use the application as a practical tool for studying adversarial machine learning, demonstrating the vulnerability of temporal action recognition models, and experimenting with inference-time and training-time attack scenarios in an accessible way.

    \item \textbf{Developers and Machine Learning Practitioners:} These stakeholders are interested in evaluating whether action recognition models such as I3D remain reliable when exposed to adversarially perturbed or poisoned video inputs. For this group, Vid-Scratch can support robustness testing and model evaluation workflows.

    \item \textbf{Project Developers and Academic Supervisors:} These stakeholders are involved in the design, implementation, and evaluation of the system. They are responsible for ensuring that the project is technically sound, aligned with its academic objectives, and usable within the defined project scope.
\end{enumerate}

The use case diagram above illustrates the main interactions between the user and the Vid-Scratch system. A single actor is used to represent all user groups identified in the stakeholder analysis because the application provides the same core workflow to all users.

    \item \textbf{\textit{User}} --- the general actor representing any person who uses the Vid-Scratch application

\section{Use Case Model}
\label{section:use-case-model}

\begin{usecase}{Upload Video}
    \textbf{Primary Actor:} User

    \textbf{Description:} The user uploads a short video file
    to the system in preparation for adversarial generation.

    \textbf{Scenario:}
    \begin{enumerate}[leftmargin=80pt]
        \item The user opens the Vid-Scratch application.
        \item The system displays the upload interface.
        \item The user selects a supported MP4 video file for upload.
        \item The system validates the file format and duration,
        then stores it for processing.
    \end{enumerate}
    \textbf{Alternative Flow:} If the file type is unsupported
    or the video exceeds one minute in length, the system
    displays an error message.
\end{usecase}

\begin{usecase}{Configure Generation Parameters}
    \textbf{Primary Actor:} User

    \textbf{Description:} The user adjusts the adversarial
    generation settings before starting the process.

    \textbf{Scenario:}
    \begin{enumerate}[leftmargin=80pt]
        \item The user navigates to the settings panel after
        uploading a video.
        \item The system displays available generation parameters,
        such as perturbation strength, optimization settings,
        and output quality.
        \item The user adjusts the settings according to their needs.
        \item The system saves the selected configuration for use
        in the generation pipeline.
    \end{enumerate}
\end{usecase}

\begin{usecase}{Start Adversarial Generation}
    \textbf{Primary Actor:} User

    \textbf{Description:} After configuring the parameters,
    the user starts the adversarial video generation process.

    \textbf{Scenario:}
    \begin{enumerate}[leftmargin=80pt]
        \item The user selects the output folder and clicks
        the Start button.
        \item The system begins the adversarial generation pipeline.
        \item The system displays a progress indicator showing
        the current processing status.
    \end{enumerate}
    \textbf{Alternative Flow:} If no video has been uploaded
    or no output folder has been selected, the system displays
    a warning message and does not start the process.
\end{usecase}

\begin{usecase}{Monitor Processing Progress}
    \textbf{Primary Actor:} User

    \textbf{Description:} The user monitors the status of
    the adversarial generation process while it is running.

    \textbf{Scenario:}
    \begin{enumerate}[leftmargin=80pt]
        \item The system updates the progress indicator as
        processing continues.
        \item The user monitors the current status of the pipeline.
        \item Once complete, the system notifies the user
        that the output video is ready.
    \end{enumerate}
\end{usecase}

\begin{usecase}{Preview Output Video}
    \textbf{Primary Actor:} User

    \textbf{Description:} The user previews the generated
    output video to verify the result before exporting it.

    \textbf{Scenario:}
    \begin{enumerate}[leftmargin=80pt]
        \item The system displays a preview of the output video
        once generation is complete.
        \item The user plays the output video to verify that it
        remains visually similar to the original and is still usable.
    \end{enumerate}
\end{usecase}

\begin{usecase}{Export Output Video}
    \textbf{Primary Actor:} User

    \textbf{Description:} The user exports the final adversarial
    output video to the designated output folder.

    \textbf{Scenario:}
    \begin{enumerate}[leftmargin=80pt]
        \item The system displays an Export button once generation
        is complete.
        \item The user clicks the button to save the output video.
        \item The system saves the processed file to the output
        folder selected by the user.
    \end{enumerate}

\end{usecase}
